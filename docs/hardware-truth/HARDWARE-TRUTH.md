## 2. 实测核对：芯片内直读 + 原理图文本抽取 ★ 本次核心

> **方法**：`ST-LINK_CLI.exe -c SWD HOTPLUG -Q -r32 <地址> <长度>`，**只读，不写入、不擦除**。
> 所有读数取"固件正常运行中"的稳态值（HOTPLUG 模式，不干扰目标）。

### 2.1 器件身份与存储器（`-List` + 只读区域）

| 读数 | 值 | 解码 |
|---|---|---|
| Device ID | `0x414` | STM32F10xx **High-density** ✅ |
| Device flash Size | `512 Kbytes` | Flash = 512 KB ✅（与 `stm32_flash.ld` 的 `LENGTH = 512K` 一致） |
| `0x1FFFF7E0` | `FFFF0200` | 低半字 **`0x0200` = 512 → Flash 512 KB** ✅（器件签名区，与型号自洽） |
| `0x08000000`（向量表 w0） | `20010000` | 复位后 **SP = 0x20010000** → RAM 顶 = 0x20000000 + 64 K → **RAM = 64 KB** ✅ |
| `0x08000004`（向量表 w1） | `08000819` | Reset_Handler = `0x08000818` → **确实从主 Flash 运行本工程固件** ✅ |
| `0xE0042000` | `10036414` | DBGMCU：DEV_ID `0x414`、**REV_ID `0x1003`** |

### 2.2 时钟树（RCC 实测）★

原始读数：`RCC_CR = 0x03034A83`、`RCC_CFGR = 0x001D040A`

| 寄存器位 | 值 | 含义 |
|---|---|---|
| `CR.HSERDY`(17) | 1 | **HSE 已起振且稳定** ✅（HSERDY 需硬件真正起振才置位） |
| `CR.PLLRDY`(25) | 1 | **PLL 已锁定** ✅ |
| `CR.HSEBYP`(18) | 0 | 使用**外部晶体**（非外部时钟输入） |
| `CFGR.SW/SWS`(1:0/3:2) | `10`/`10` | **系统时钟 = PLL** ✅ |
| `CFGR.HPRE`(7:4) | `0000` | AHB 不分频 → **HCLK = 72 MHz** |
| `CFGR.PPRE1`(10:8) | `100` | **APB1 = HCLK / 2 = 36 MHz** |
| `CFGR.PPRE2`(13:11) | `000` | **APB2 = HCLK / 1 = 72 MHz** |
| `CFGR.PLLSRC`(16) | 1 | PLL 输入 = **HSE** ✅ |
| `CFGR.PLLXTPRE`(17) | 0 | HSE 不分频 |
| `CFGR.PLLMUL`(21:18) | `0111` | **×9** → 8 MHz × 9 = **72 MHz** ✅ |
| `RCC_BDCR` | `0x00000000` | **LSE 未开启** → 32.768 kHz 晶振未使用、无 RTC |
| `RCC_APB1ENR` | `0x00000000` | 无任何 APB1 外设（无 I2C / USART2-3 / TIM2-7 / SPI2） |
| `RCC_APB2ENR` | `0x000001E8` | 仅 **GPIOB/D/E/F/G**（bit3/5/6/7/8）；**GPIOC 未开时钟**、AFIO 未开 |
| `RCC_AHBENR` | `0x00000114` | SRAMEN + FLITFEN + **FSMCEN** ✅ |

> **结论**：`HCLK = 72 MHz` 不再只是"文档/代码里写的"，而是**从芯片读出来的** —— 这正是教程时序（按 36 MHz 写）在本板白屏的根本原因。
> **HSE = 8 MHz 属间接确认**（HSERDY=1 + PLLMUL=9 + 屏在 72 MHz 时序下正常）；绝对频率仍建议示波器复核（V-002）。

### 2.3 复位来源（附带发现）

`RCC_CSR = 0x1C000000` → `SFTRSTF | PORRSTF | PINRSTF` 同时置位。

| 位 | 含义 |
|---|---|
| `SFTRSTF`(28) | 发生过**软件复位** —— 与"`ST-LINK_CLI` 每次连接都会复位目标"一致 |
| `PORRSTF`(27) | 发生过**上电复位** |
| `PINRSTF`(26) | 发生过**NRST 引脚复位** |

> 顺带说明：这些标志位只读、不影响功能。**不要为了"清零"去写寄存器**（AGENTS.md 闸门：不写入目标）。

### 2.4 FSMC 时序（本板最关键的一条配置）★

原始读数（`FSMC_R_BASE = 0xA0000000`，实测值与头文件 `stm32f10x.h` L1282 一致）：

```
0xA0000000 : BCR1=000030DB  BTR1=0FFFFFFF  BCR2=000030D2  BTR2=0FFFFFFF
0xA0000010 : BCR3=000030D2  BTR3=0FFFFFFF  BCR4=00003091  BTR4=0FFFFFFF
```

| bank | 用途 | BTR | ADDSET(bits3:0) | DATAST(bits15:8) | 结论 |
|---|---|---|---|---|---|
| 1 (NE1) | 未使用 | `0x0FFFFFFF` | 15 | 255 | 未被固件改写 |
| 2 (NE2) | 未使用 | `0x0FFFFFFF` | 15 | 255 | 未被固件改写 |
| 3 (NE3) | 未使用 | `0x0FFFFFFF` | 15 | 255 | 未被固件改写 |
| **4 (NE4)** | **LCD（CS = PG12）** | **`0x0FFFFFFF`** | **15** ✅ | **255** ✅ | **与文档记载完全一致** |

**BCR4 的逐位还原**（把固件的写入动作套在读数上，能完全对上，证明解读无误）：

| 位 | 名称 | 头文件宏 | 原值 `0x30D2` | 读数 `0x3091` | 固件动作 |
|---|---|---|---|---|---|
| 0 | MBKEN | `0x00000001` | 0 | **1** | `\|= MBKEN` 置 1 ✅ |
| 1 | MUXEN | `0x00000002` | 1 | **0** | `&= ~MUXEN` 清 0 ✅ |
| 3:2 | MTYP | `0x0000000C` | 00 | 00 | `&= ~MTYP` → 本就 00（SRAM/ROM）✅ |
| 5:4 | MWID | `MWID_0 = 0x10` | 01 | 01 | `\|= MWID_0` → 本就 16bit ✅ |
| 6 | FACCEN | `0x00000040` | 1 | **0** | `&= ~FACCEN` 清 0 ✅ |
| 12 | WREN | `0x00001000` | 1 | 1 | `\|= WREN` → 本就 1 ✅ |

> ⚠️ **读数注意事项（重要，避免误判）**：
> 1. `BTRx` 的**复位值是 `0x0FFFFFFF`**（所有字段全 1，含保留位），而 `ADDSET=15 / DATAST=255` 恰好也是最大值 →
>    **无法从读数区分"固件写入生效"还是"保持复位值"**。可确认的是：**芯片内 NE4 的实际时序就是 15 / 255**（这才是硬件事实）。
> 2. 其他字段（BUSTURN / CLKDIV / DATLAT / ACCMOD）在 `MTYP = SRAM` 下**无意义**，不要去解读它们。
> 3. 本工程只配置 **NE4**；bank1~3 保持上电默认值，属正常，**不是漏配**。
> 4. ⚠️ **板上另有 FSMC 器件**：SDRAM（**`ISSI IS62WV51216BLL-55TLI`**，512 K×16，实物照片已确认）与屏**共用 FSMC D0~D15**，
>    必然占用 NE1~NE3 中的一个 bank（**具体哪个 bank 待核对原理图对应页**，原理图页 12 只画了 LCD）。
>    本工程未初始化它 → **该器件当前不可访问，属设计取舍**（将来要用需另配 bank 与地址线）。

### 2.5 GPIO 实测（逐引脚核对）

各端口 `CRL/CRH` 原始读数与解码（nibble 值：`B` = 复用推挽 50 MHz，`3` = 通用推挽 50 MHz，`4` = 浮空输入，`8` = 输入带上下拉）：

| 端口 | CRL | CRH | IDR | ODR | 结论 |
|---|---|---|---|---|---|
| GPIOB | `44484443` | `44444444` | `0000FFD5` | `00000011` | **PB0 = 通用推挽（背光）**；PB4 = 输入带上下拉（JTAG NJTRST 复位默认）；PB6/PB7 是**浮空输入**（触摸 I2C 未配置，与"未使用"一致） |
| GPIOC | `44444444` | `44444444` | `0` | `0` | **时钟未开（APB2ENR bit4 = 0）→ 读数不代表实际配置，不作判据** |
| GPIOD | `44BB44BB` | `BB444BBB` | `00000F3C` | `0` | `PD0 PD1 PD4 PD5` + `PD8 PD9 PD10 PD14 PD15` = **复用推挽** ✅（FSMC D0~D15 + NOE/NWE） |
| GPIOE | `B4444444` | `BBBBBBBB` | `0000FF38` | `0` | `PE7` + `PE8~PE15` = **复用推挽** ✅（FSMC D4~D12）；PE0~PE6 未用 |
| GPIOF | `44444444` | `44444444` | `00000F01` | `0` | 未使用（复位默认） |
| GPIOG | `4444444B` | `344B4444` | `0000F7E5` | `00008000` | **PG0 = 复用推挽（A10/RS）** ✅；**PG12 = 复用推挽（NE4/CS）** ✅；**PG15 = 通用推挽（RST）** ✅ |

**由 IDR（引脚实际电平）读到的客观电学事实**：

| 引脚 | IDR 位 | 实测电平 | 说明 |
|---|---|---|---|
| **PB0**（背光） | bit0 = 1 | **高** ✅ | 背光确实点亮（`ODR` bit0 = 1） |
| **PG12**（CS） | bit12 = 1 | **高** ✅ | 片选空闲态为高（正常） |
| **PG15**（RST） | bit15 = 1 | **高** ✅ | 复位已释放（`ODR` bit15 = 1，未处于复位状态） |
| PD4 / PD5（NOE/NWE） | bit4/5 = 1 | **高** ✅ | 读/写选通空闲态为高（正常） |

> **结论**：`AGENTS.md` 与 `HARDWARE.md` 里的引脚表（含 PG12/PG0/PD5/PD4/PG15/PB0 + 16 条数据线）**与芯片内的真实配置逐条一致** ✅。
> 这是"接线表 ↔ 固件 ↔ 硅"三方闭环，至此引脚部分 **不再需要靠人肉眼核对**。

### 2.6 选项字节（只读，`0x1FFFF800`）

```
0x1FFFF800 : 00FF5AA5  00FF00FF  00FF00FF  00FF00FF
```

| 字节位置 | 值 | 含义 |
|---|---|---|
| `0x1FFFF800` = **RDP** | **`0xA5`**（补码 `0x5A` 校验通过） | **读保护 Level 0 —— 未启用读保护** ✅ 芯片未被锁死 |
| `0x1FFFF802` = USER | `0xFF` | `nRST_STDBY/nRST_STOP = 1`（不产生复位）、**`WDG_SW = 1`（独立看门狗由软件控制）**、**`nBOOT1 = 1` → BOOT1 = 0** |
| WRP0~3 | 均 `0xFF`（补码 `0x00`） | **写保护全部未启用** |

**得到的推论**：
- **启动模式**：`nBOOT1 = 1` → BOOT1 = 0 → 启动位置由 **BOOT0 引脚**决定（低 = 主 Flash）。实测固件从 Flash 正常运行 → **BOOT0 实际为低电平** ✅。
- 但 **BOOT0 是否由板上电阻下拉**（还是靠 ST-Link/外部给的低）→ **`UNKNOWN`**，需看原理图/实物（V-003）。
- ⚠️ **绝不要写入选项字节**（AGENTS.md §5 闸门）；本次仅读取。
