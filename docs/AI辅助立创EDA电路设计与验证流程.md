# AI 辅助立创EDA 电路设计与验证流程（2026）

> **定位**：本文回答两个问题——**① 嘉立创/立创EDA 到底支不支持 AI 画电路图？② 画出来的板子怎么验证？**
>
> **一句话结论**：支持，但形态是"**AI Agent 外挂操控 EDA**"，而不是软件内一键生成；产出是"**AI 辅助绘图**"，**不能直接投板**，必须走四层验证。
>
> **配套文档**：`docs/AI-PCB设计工具与Skill全景.md`（**工具选型地图**：有哪些 AI PCB 工具与 Skill、各自边界）、`docs/AI用于嵌入式的最佳实践.md`（方法论）、`docs/Win11-AI嵌入式工程落地方案.md`（固件侧护栏与验证闭环）。本文的"四层验证"与那篇的"验证闭环"是同一套思想的硬件侧落地；本文是全景文档中"立创 EDA 路线"的具体落地。

---

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 立创EDA 有官方 AI 能力吗？ | 有。官方维护 `easyeda-api-skill`（Agent Skills），走 `Run API Gateway` 桥接运行中的 EDA Pro |
| 只能用它自家的 AI 吗？ | 不是。只要是支持 **Agent Skills** 或 **MCP** 的 AI 客户端（Claude Code、Cursor、Windsurf、OpenCode、QwenCode…）都能接 |
| 能"一句话出完整板子"吗？ | 不能。能一键出**原理图骨架**（秒级），PCB 布局布线需人工或额外工具；元件选型 AI 会"自作主张" |
| 生成后能直接下单打样吗？ | **绝对不行**。必须过 ERC → 网表比对 → DRC → DFM → 人工复核 → 首板上电测试 |
| 验证靠什么？ | 四层：原理图逻辑 → PCB 规则/可制造性 → AI 复核闭环 → 实物实测（不可省） |

## 1. AI 接入立创EDA 的两条路线

### 1.1 对比

| 维度 | easyeda-api-skill（官方） | jlcmcp / LCEDA-Agent 等（社区 MCP） |
|---|---|---|
| 来源 | 嘉立创官方（`github.com/easyeda/easyeda-api-skill`） | 社区开发者（如 `github.com/hyl64/jlcmcp`） |
| 协议 | Agent Skills | Model Context Protocol (MCP) |
| 工具粒度 | 覆盖 120+ 类 API 文档，粒度**粗**，但上手最快 | 拆成 39~59 个细粒度结构化工具（各社区项目口径不一，以仓库 README 为准） |
| 兼容客户端 | Claude Code、OpenCode、QwenCode 等 | Claude Code、Cursor、Windsurf 等一切支持 MCP 的客户端 |
| 典型能力 | 一句话生成完整原理图 + 跑 DRC | 单步可控：加电阻 / 设网络标签 / 走线 / 过孔 / 铺铜 / ERC / DRC 自修复 / 设计健康报告 |
| 适合谁 | 学生、爱好者、快速搭验证板 | 工程师、需要精确控制选型与布局的场景 |

### 1.2 官方 Skill 的接入三步

1. **AI 端**：把仓库地址丢给 AI，让它"帮我安装这个 skill"（或手动下载 zip 放进 skill 目录后重启客户端）。
2. **EDA 端**：`立创EDA Pro → 高级 → 扩展管理器 → 搜索 "run" → 安装` 网关插件。安装后**必须勾选全部与 Run API Gateway 相关的权限项**，否则 AI 无法与 EDA 通信。
3. **建立连接**：本地启动 API 服务，看到"连接成功"提示即代表 AI 客户端已能与立创EDA 对话。

### 1.3 硬性前提

- **必须用立创EDA 专业版**——网页标准版**没有**扩展 API，接不了；
- 机器需同时跑 EDA + AI 客户端 + 本地服务，**建议 ≥ 8GB 内存**；
- 首次使用确认防火墙没拦本地端口（常见 **3000 / 8080**）；
- 走 MCP 路线还需 Node.js 环境（`npm install` → `npm start` → 在客户端填 `http://localhost:3000`）。

### 1.4 已知限制（务必先读）

| 限制 | 后果 | 应对 |
|---|---|---|
| 粒度粗、会"自作主张" | 你要 Type-C 供电，它给你 Micro USB 插座 | 用 MCP 细粒度工具分步执行；或明确写死型号 |
| 元件型号可能被替换 | LDO 从 TPS7A4700 变成 AMS1117 | 要求"不得更换指定型号"，并**逐个核对 BOM** |
| 依赖 Agent Skills 标准 | 官方 Skill 兼容的客户端范围窄 | 更广兼容性选 MCP 路线 |
| API 非流式 | 无法边生成边返回 | 分步操作，降低单次任务复杂度 |
| 页面刷新闪烁等已知问题 | 体验受损 | 关注官方更新日志 |

> ⚠️ 以上信息来自 2026 年公开资料与社区实测，**版本迭代快，接入细节请以官方仓库/社区文档为准**。

## 2. 四层验证方法（核心内容）

> 原则：**AI 生成的原理图不能直接投板**。工具能证明的只是"结构合法"，电气正确性与行为正确性必须由人 + 硬件确认。

```
第 1 层  原理图逻辑验证   ERC · 网表比对 · BOM/封装核对 · SPICE 仿真
        ↓（逻辑先对，再动 PCB）
第 2 层  PCB 规则与可制造性  实时 DRC · 完整 DRC · 嘉立创 DFM · Gerber 回看 · 3D
        ↓
第 3 层  AI 复核闭环       把上面的报告回灌给 AI 定位/自修复，人工确认
        ↓（设计冻结）
第 4 层  实物验证（不可省）  阻抗/短路 → 限流上电 → 逐路测压 → 示波器 → 烧录 → 功能/老化
```

### 2.1 第 1 层：原理图逻辑验证（最容易被 AI 骗的一层）

| 手段 | 查什么 | 说明 |
|---|---|---|
| **ERC 电气规则检查** | 悬空网络、单端网络、引脚类型冲突（两个输出直连）、电源未接 | EDA 内置，AI 也可通过 MCP 工具触发 |
| **网表比对（netlist diff）** | AI 生成的网表 vs 你的需求清单/参考设计 | **抓 AI 幻觉最有效的手段**；重点看 GND 是否真正全局连通、电源域是否串错 |
| **器件参数 + 封装复核** | 阻容值、极性、封装引脚间距 | **封装错比连线错更致命**（板子直接废）；逐项对实物 datasheet |
| **SPICE 仿真** | 电源分压、LDO 稳定性、复位时序、晶振起振 | 立创EDA 支持仿真；只覆盖无源/模拟小电路，别指望它验证 MCU 逻辑 |
| **引脚复用核对** | 与固件侧 `AGENTS.md` 的引脚表是否一致 | 原理图 IO 分配错了，固件白写 |

**AI 生成电路的典型缺陷**（高频出现，逐条查）：

- GND 符号"看着连了"但实际是多个孤立网络；
- 去耦电容漏放或放错电源域；
- 复位电路缺上拉；
- 晶振缺负载电容或负载电容取值照抄别的型号；
- SWD 接口缺上拉/缺 TVS；
- 未用引脚未处理（悬空导致漏电或误触发）；
- 电源网络命名不统一（`3V3` / `VCC3V3` / `+3.3V` 混用 → 实际断开）。

### 2.2 第 2 层：PCB 规则与可制造性

| 手段 | 工具 | 查什么 |
|---|---|---|
| **实时 DRC** | 立创EDA PCB 编辑器（菜单：设计 → 实时DRC） | 边画边报错，违反规则处显示黄色 X 标识 |
| **完整 DRC** | 立创EDA（设计 → 检查DRC） | 线宽/线距、最小孔径、环宽、焊盘间距、铜到板边 |
| **DFM 可制造性检查** | **嘉立创 DFM**（`jlc-dfm.com`），直接上传 Gerber 或 PCB 源文件 | 线路、阻焊、丝印、钻孔等 **30 多项**检测，一键输出问题报告 |
| **Gerber 逐层回看** | DFM / Gerber Viewer | 阻焊开窗是否压焊盘、丝印是否压焊盘、拼板与工艺边、外形层与实际板框一致 |
| **3D 预览** | 立创EDA 3D 视图 | 元件高度干涉、连接器开口方向、装配可行性 |
| **叠层与阻抗** | 嘉立创阻抗计算器 / EDA 层叠管理器 | 只有高速信号（USB/以太网/DDR/差分对）才需要；核对线宽与参考层 |

**DRC 通过 ≠ 能制造**：DRC 只保证"符合你设的规则"；DFM 才回答"嘉立创的工艺能不能做出来"。两步都要跑。

### 2.3 第 3 层：AI 复核闭环

这一层的价值是**把机器可读的报告变成定位结论**，而不是让 AI 替你判断。

| 做法 | 具体操作 |
|---|---|
| 报告回灌定位 | 把 ERC/DRC/DFM 导出的问题清单（含坐标）贴给 AI，要求"按严重度排序 + 给出修改位置与理由"，逐条人工确认 |
| MCP 自修复 | 社区 MCP 提供 DRC 自修复、设计健康报告类工具；**必须在 git/版本管理下操作**，改完重新跑 DRC 验证 |
| 独立 AI 检查器 | 已有基于 MCP 的原理图检查助手，可读取**器件参数、引脚类型、网络连接、坐标**维度做检查；注意其 API **非流式**、有页面刷新闪烁等已知问题，且定位是"检查"（只读分析）而非自动修改 |
| 交叉复核 | 用**不同模型/不同工具**各查一遍，比同一个 AI 自查更有效（与固件侧"模板 3 让 AI 当 reviewer"同理） |

### 2.4 第 4 层：实物验证（不可省）

```
① 目视 + 万用表：测电源对地阻抗，先排除短路/焊接桥连
② 限流上电：0.1~0.5 A 限流，观察电流是否异常
③ 逐路测压：VIN → LDO/DC-DC 输出 → MCU VDD → 参考电压，逐点确认
④ 示波器：晶振起振与频率、复位时序、电源纹波与上电斜率、关键时钟
⑤ 逐模块点亮：LED → 串口日志 → 传感器 I2C/SPI 读 ID → 外设
⑥ SWD 连接 + 烧录，跑固件
⑦ 功能测试 → 温升/长时间运行（老化）→ 边界条件（低压/高温/冷启动）
```

> 与固件侧的对应关系：第 ①~④ 步等价于"上板实测"，绝不能用"AI 说应该没问题"或"DRC 全绿"代替。这一步的结论要回写到 `AGENTS.md` / 设计文档，作为下一版的事实依据。

## 3. 人工必查清单（打印出来逐条打勾）

### 3.1 原理图（设计冻结前）

- [ ] 电源网络：命名统一、极性正确、每个电源引脚都有去耦
- [ ] GND：**确认是同一个网络**（不是多个同名孤立网络）
- [ ] 复位电路：上拉电阻存在且阻值合理，复位电容齐全
- [ ] 晶振：负载电容匹配（按晶体 datasheet 算）、有匹配电阻
- [ ] 调试口：SWD 上拉 / 必要时 TVS，接口定义与调试器一致
- [ ] 未用引脚：明确接地 / 上拉 / 配置为模拟或其他确定状态
- [ ] 元件型号：与 BOM 一致，**逐个核对 AI 有没有偷换**
- [ ] 封装：与实物 datasheet 的引脚间距、极性、焊盘尺寸一致
- [ ] 引脚分配：与固件侧 `AGENTS.md` 引脚表一致
- [ ] ERC 零未处理告警

### 3.2 PCB（下单前）

- [ ] 完整 DRC 通过，无遗留错误（不是"忽略"）
- [ ] 嘉立创 DFM 检查通过，或问题已逐项确认可接受
- [ ] Gerber 与 PCB 源文件版本一致（**最容易出错**：导出旧版本）
- [ ] 阻焊、丝印不压焊盘；丝印方向与装配图一致
- [ ] 板框与外形层一致，拼板/工艺边符合厂家要求
- [ ] 元件位号丝印完整（装配与维修需要）
- [ ] 3D 视图无干涉，连接器开口方向正确
- [ ] 高速信号（如有）阻抗与参考层核对完成

### 3.3 首板（上电前）

- [ ] 目视检查虚焊/连锡/元件方向
- [ ] 万用表测电源对地阻抗，排除短路
- [ ] 准备好限流电源与示波器
- [ ] 记录本次实测结果（用于回写文档）

## 4. 与固件侧验证闭环的衔接

硬件侧的验证要能和固件侧的护栏对接，才形成完整闭环：

| 硬件侧产物 | 固件侧对应 | 作用 |
|---|---|---|
| 原理图引脚分配表 | `AGENTS.md` §1 引脚映射表 | 防止 AI 生成引脚冲突的初始化代码 |
| 各电源域电压/时序 | `AGENTS.md` §1 硬件事实 | 防止 AI 假设错误的时钟/上拉配置 |
| 首板实测结论 | `AGENTS.md` 变更记录 | 让"实测过"成为唯一可信来源 |
| DFM / 原理图设计文件 | 版本控制（Git） | 任何 AI 修改都可 diff、可回滚 |

> 铁律：**AI 改硬件设计文件，必须与改代码同等对待**——小步提交、可 diff、可回滚、改完必须重跑 DRC/DFM。

## 5. 常见陷阱速查

| 症状 | 真实原因 | 处理 |
|---|---|---|
| AI 说"DRC 通过"，上板却不通 | DRC 只查几何规则，不查电气逻辑 | 必须单独做网表比对与人工查表 |
| 板子到手发现某个网络没连上 | GND/电源被拆成多个孤立同名网络 | 用网络管理器检查网络数量，而非只看符号是否相连 |
| 元件焊不上 | 封装与实物不符（AI 默认选了错封装） | 逐项核对封装与 datasheet 的 land pattern |
| 你要 Type-C 结果是 Micro USB | 官方 Skill 粒度粗，"自作主张"换件 | 显式写死接口与型号；改用细粒度 MCP 分步执行 |
| 交互式 AI 操作 EDA 卡顿/闪烁 | 已知问题：API 非流式、页面刷新闪烁 | 拆小任务；关注官方更新 |
| 上传 Gerber 后 DFM 报一堆问题 | EDA 里 DRC 规则设得太松，或导出了旧版本文件 | 先确认导出的是最新版本，再按 DFM 报告逐项修 |
| AI 越权改设计文件 | 缺少审批闸门 | 硬件设计文件改动必须人工确认 + 版本控制 |
| 原理图"看着对"但时序不对 | 上电顺序、复位时序未验证 | 示波器实测上电时序，别信估算 |

## 6. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| AI 生成的电路直接投板 | 报废 PCB + 元件 + 打样周期 | 四层验证 + 人工必查清单，禁止跳过 |
| AI 静默替换元件型号 | BOM 成本/性能偏离设计意图 | 逐个核对 BOM；要求 AI 输出"与需求的差异清单" |
| 设计文件被 AI 批量改动 | 无法定位是哪一步改坏的 | Git 版本控制 + 小步提交 + 改完重跑 DRC/DFM |
| 过度信任 DFM 通过 | 忽略电气逻辑与装配问题 | DFM 只管可制造性，电气与装配仍需人工 |
| 把厂商/专有设计喂给云端模型 | IP 泄露 | 参照方法论文档：敏感设计用本地模型 |

**回滚**：AI 对 EDA 的所有操作都是**设计文件内的改动**，用 Git（或 EDA 自带历史版本）回退即可；**不要**用"再让 AI 改回去"的方式恢复。

---

## 7. 最小可落地子集（时间有限时只做这些）

1. **接官方 Skill 或一个 MCP**，让 AI 能画原理图骨架（省掉 80% 的手动连线时间）；
2. **ERC + 网表比对 + 人工必查清单 §3.1** —— 这一步拦住的就是"AI 幻觉"类致命错误；
3. **完整 DRC + 嘉立创 DFM 双跑**，再下单打样；
4. **首板限流上电 + 逐路测压**，不省。

这四件事做完，AI 在硬件侧的角色就从"会画错线的实习生"变成"省掉重复劳动的实习生"。
